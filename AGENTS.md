# Portfolio working rules

- Public site language: Polish. Discuss work with Denys in Russian.
- Positioning: AI/automation, IT administration, cybersecurity learning. Show the actual scope of each project; do not imply commercial experience or certifications not confirmed by Denys.
- Use APPLI as the product name. Do not use the retired personal project name.
- Keep project claims in `content/projects.json`. Reuse entries across perspectives rather than copying divergent descriptions.
- Content and screenshots must be grounded in supplied material or directly verified evidence. Do not generate fake product screenshots, credentials, metrics, testimonials or completion claims.
- Keep planned work distinct from working processes. Audio Studio and the manual transcription workflow are separate completion states.
- Do not expose keys, server credentials, private IP inventories, personal finance data, unapproved recordings or private source repositories.
- Work in a task branch. Preserve other changes. Do not alter other websites, Caddy blocks, server access or DNS records outside this portfolio task.
- Run `npm run build` and `npm run check`; verify changed interactions in a browser when available.
- Update `docs/HANDOFF.md` with completed work, checks and real blockers.
- Deployment instructions and scripts are preparation until execution and visible HTTPS checks establish a live deployment.
- The site must remain usable on mobile, support keyboard navigation, respect reduced motion and include meaningful image alt text.
- Do not silently rewrite a reviewed or previously sent CV. Generation and content review are distinct steps.
