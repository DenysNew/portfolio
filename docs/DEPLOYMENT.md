# Размещение на существующем сервере

Целевой адрес: `portfolio.appli-lab.pl`. Первая публикация выполнена 2026-11-12; проверенный выпуск и точный откат — в [HANDOFF](HANDOFF.md).

## Перед первым размещением

1. Подтвердить сервер Audio Studio, актуальный публичный IP и существующий SSH-доступ. Не использовать старый адрес как автоматически актуальный.
2. Прочитать действующую конфигурацию Caddy и список сайтов; сохранить резервную копию перед добавлением блока.
3. Создать `/var/www/portfolio/releases` с правом записи для существующего пользователя публикации и правом чтения для Caddy. Не делать каталог доступным на запись всем пользователям.
4. Проверить существующую A-запись `portfolio` и AAAA. На первой публикации A уже была настроена, AAAA отсутствовала; DNS не менялся. Добавлять запись только при её отсутствии и согласованном размещении.
5. Проверить существующую доступность HTTP/HTTPS. Не менять SSH, IAM или другие сетевые правила без необходимости для согласованной задачи.

## Публикация файлов

На рабочем сервере, где уже настроен SSH-псевдоним сервера приложения:

```bash
bash scripts/deploy.sh audio-app
```

`audio-app` — ожидаемый псевдоним, его наличие сначала проверяется. Скрипт требует чистый Git checkout, собирает и проверяет сайт, передаёт только `dist/`, создаёт новый каталог выпуска и переключает `current`. Не запускается из среды без настроенного SSH.

На первой публикации использована эквивалентная процедура с дополнительной проверкой: свежий `dist/` из чистого checkout передан в отдельный выпуск; SHA-256 всех 9 файлов проверены на сервере **до** переключения `current`. Поставляемый скрипт проверяет наличие `index.html`, но не полный манифест передачи. Для повторной публикации сохранять такую же полную проверку до переключения.

## Caddy

Добавить блок из `deploy/Caddyfile.example` в действующую конфигурацию, сохранив остальные сайты. Корень сайта: `/var/www/portfolio/current`.

```bash
sudo caddy validate --config /etc/caddy/Caddyfile --adapter caddyfile
sudo systemctl reload caddy
```

Перезагрузка выполняется только после успешной проверки. Обычные обновления статических файлов не требуют перезапуска Caddy.

## Приёмка

- Домен открывается по HTTPS; HTTP перенаправляет на HTTPS.
- Открываются `/#ai`, `/#admin` и `/#security`.
- Скачивается правильный PDF; ссылки и изображения работают.
- Корень сайта не выдаёт список файлов; служебные файлы репозитория не публикуются.
- Существующие сайты сервера продолжают работать.

## Откат

Сохранить предыдущий каталог в `releases/`. При необходимости переключить `current` обратно на **точно известный предыдущий выпуск** через временную символическую ссылку и `mv -T`. После переключения проверить страницу. Не удалять выпуски автоматически.

## Последующая автоматизация

Текущий CI только собирает и проверяет сайт. Автоматическая публикация с GitHub требует отдельного согласованного способа доступа к серверу. Не добавлять приватный SSH-ключ в репозиторий и не предоставлять общий root-доступ для CI.
